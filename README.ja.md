<h1 align="center">Cleat</h1>
<p align="center"><sub>by <a href="https://jetto.ai">Jetto</a></sub></p>

<p align="center">Mac のオーディオデバイスを、あなたが決めた場所に留めておきます。<br>正しいスピーカーから音を出し、正しいマイクを正しい音量に保ち、AirPods をスマートフォンから取り戻します。</p>

<p align="center"><a href="README.md">English</a> · <a href="README.zh-TW.md">繁體中文</a> · <a href="README.zh-CN.md">简体中文</a> · <b>日本語</b> · <a href="README.ko.md">한국어</a></p>

クリート（cleat）は、ロープを結んで船が流されないようにする金具です。この Cleat はオーディオデバイス用です。どの出力、どのマイク、どの音量、どのバランスにしたいかを伝えれば、Cleat がそれを保ちます。ポーリングではなく CoreAudio のイベントに反応するので CPU はほとんど使いません。普段はメニューバーにいて、保っている項目はすべて設定ウインドウで変更できます。

macOS はオーディオデバイスを勝手に動かします。AirPods Max をつなぐとマイクを奪われます（Bluetooth も通話品質の HFP に落ちます）。ビデオ会議アプリは「マイク音量を自動調整」して、別の値のまま放置します。仮想マシンは起動するたびに出力音量を変えます。何度か再接続するとバランスが中央からずれます。スマートフォンに貸した AirPods はスマートフォン側に残り、Mac はその日ずっとスピーカーから鳴ります。そして送信機の電源が切れたワイヤレス受信機も、CoreAudio から見れば普通のデバイスで、ただ無音を送り続けています。

**Cleat がすること**

- **出力の優先順位。** リストの中で最初に接続されているデバイスから音を出します。「使わない」にしたデバイスは、macOS が自分で切り替えた場合でも外します。
- **マイクの優先順位。** リストの中で最初に接続されているマイクがデフォルト入力になります。ブロックリストで AirPods Max（や Zoom、Teams の仮想デバイス）をその席に入れません。
- **Bluetooth ヘッドフォンが接続されたら切り替え。** ヘッドセットがつながると、有線ヘッドフォンと同じように音がそちらへ移ります。
- **AirPods をスマートフォンから取り戻す。** リストに入れたヘッドセットが接続されているのに音声がスマートフォンや iPad 側にあり、Mac で再生中で、あなたが Mac の前にいるとき、Cleat はそれを取り戻します。スマートフォンで実際に再生中や通話中なら、スマートフォンに残します。
- **マイク音量を固定。** すべてのマイクに 1 つの値、デバイスごとに個別の値も設定できます。
- **指定したプログラムによる出力音量の変更を元に戻す。** Parallels Desktop（または追加した任意のアプリ）が出力音量を変えると、Cleat が戻します。あなた自身の変更はそのまま残ります。
- **バランスを中央に固定**（または設定した位置に）。
- **完全な無音のデバイスは存在しないものとして扱う。** デジタル無音だけを送る受信機は飛ばされ、リストの次のマイクが引き継ぎます。
- **あなたの選択には手を出さない。** どちらのリストにもない、自分で選んだマイクはそのまま残ります。
- **設定ウインドウとメニューバー項目**。いま使われているデバイスと、Cleat 自身の CPU とメモリ使用量を表示します。

## 保つもの

6 つのルールは同じ形をしています。CoreAudio のプロパティを購読し、設定ファイルと比べ、違っていれば書き戻します。出力音量のルールは、どのプログラムが変更したかも知る必要がありますが、CoreAudio はそれを教えてくれないので、システムログから読み取ります。ヘッドセットを取り戻すルールは、別のデーモンにヘッドセットを返すよう依頼します。スマートフォンに取られたヘッドセットは、書き込める CoreAudio のプロパティではないからです。

| | 内容 | 設定 |
|---|---|---|
| 1 | 入力デバイスの優先順位とブロックリスト | `input`、`blockedInput` |
| 2 | 完全なデジタル無音を送るデバイスを存在しないものとして扱う | `liveness` |
| 3 | 出力のバランスを固定 | `balance` |
| 4 | 出力デバイスの優先順位とブロックリスト | `output`、`blockedOutput` |
| 5 | デバイスごとに入力音量を固定 | `inputVolume` |
| 6 | Bluetooth ヘッドフォンが接続されたら出力を引き継ぐ | `headphonesTakeOver` |
| 7 | スマートフォンに取られた Bluetooth ヘッドセットを取り戻す | `reclaim`、`reclaimEnabled` |
| 8 | 指定したプログラムによる出力音量の変更を元に戻す | `outputVolumeHoldAgainst`、`outputVolumeHoldEnabled` |

自分で選んだデバイスを奪うことはありません。現在のデフォルト入力が優先順位にもブロックリストにもない場合（システム設定で選んだマイクや、Zoom、Teams の仮想デバイスなど）、Cleat は手を出しません。

## 設定ウインドウとメニューバー

デーモンはメニューバーに項目を置きます。そのメニューには、いま使われている出力と入力が表示され、設定ウインドウを開く、「このアプリについて」を表示する、Cleat を終了する、の操作ができます。

設定ウインドウには出力、入力、ヘッドフォンの 3 ページがあります。各ページの上部にはステータスカードがあり、Cleat が動いているかどうか、CPU（1 コアがフルで 100%、直近 1 分の平均、アクティビティモニタと同じ計算）、メモリ（アクティビティモニタの「メモリ」列と同じ値）、引き戻し速度（何かに設定を変えられてから Cleat が戻すまでの時間、直近数回の中央値）を表示します。

- **出力**：優先順位リスト、ほかのすべての出力デバイス（それぞれに「順位に追加」ボタンと「使わない」チェックボックス）、音量の変更が元に戻されるプログラムの一覧（最後に戻した時刻つき）、ライブの値つきのバランス。
- **入力**：マイクの優先順位リスト、ほかのすべての入力デバイス、音量（すべてのマイク共通のスライダー 1 本と、追加したデバイスごとのスライダー）。
- **ヘッドフォン**：自動切り替えのスイッチ、取り戻しのスイッチ、ペアリング済みの Bluetooth ヘッドセットごとのチェックボックス。システムがオーディオとして識別しない Bluetooth デバイスは折りたたまれたグループにまとめられ、自分の種類を名乗らないスピーカーやヘッドフォンはそこでチェックします。

優先順位リストのデバイスを右クリックすると、上下に移動できます。変更はすべて少し後に設定ファイルへ書き込まれ、デーモンはそこから読み取ります。ウインドウに表示されないキーはそのまま残ります。ウインドウを開いている間にディスク上の設定ファイルが変更されると、ウインドウは書き込みを止め、再読み込みを提案します。

開き方は、メニューバー項目、`cleat settings`、またはデーモンの実行中に Finder、Spotlight、Raycast から Cleat.app を開く方法があります。設定ウインドウは同時に 1 つしか開きません。

## インストール

```sh
brew tap jettoai/tap
# Homebrew requires third-party taps to be trusted before it will load their casks.
brew trust jettoai/tap
brew install --cask cleat
```

または [Releases](https://github.com/jettoai/cleat/releases) から zip をダウンロードし、`/Applications` に展開して一度開きます。

続いて設定ファイルを書いて起動します。

**コピーする前にサンプルを読んでください。** これは作者自身の設定で、中立な出発点ではありません。すべての入力デバイスの音量を 100% に固定し（`"inputVolume": {"*": 100, ...}`）、ヘッドフォンの自動切り替えもオンにしているので、Bluetooth ヘッドセットはつながった瞬間に出力になります。中のデバイス名は作者のものなので、デバイスを名指しするルールは、あなた自身のデバイス名に置き換えるまで何もしません。ただしデバイスを名指ししない 2 つの設定はすぐに効きます。`balance` は現在の出力を中央に戻し、`launchAtLogin` は Cleat をログイン項目として登録します。先に自分のデバイスに合わせて編集するか、`{}` から始めてルールを 1 つずつ追加してください。編集は設定ウインドウに任せることもできます。

```sh
mkdir -p ~/.config/cleat
cp /Applications/Cleat.app/Contents/Resources/config.example.json ~/.config/cleat/config.json
cleat restart
```

`cleat restart` はアプリに同梱された launchd エージェントを登録し、それを通してデーモンを起動します。以降は launchd がログイン時に Cleat を起動し、強制終了やクラッシュの際にも再び起動します。通常の終了（メニューの「Cleat を終了」や、`brew upgrade` による旧バージョンの置き換え）は意図的にそのままにします。Cleat は次のログイン時、アプリをもう一度開いたとき、または `cleat restart` で戻ってきます。`cleat status` でエージェントがどの状態にあるかがわかります。`launchAtLogin` を `false` にするとエージェントの登録が解除され、Cleat も終了します。

手動でインストールする場合は、Finder からアプリを一度開きます。これが最初のマイク許可の確認であり、エージェントを登録するタイミングでもあります。エージェントの実行中にアプリをもう一度開くと設定ウインドウが開くので、デーモンが 2 つになることはありません。

## 設定ファイル

`~/.config/cleat/config.json`。保存してから 1 秒以内に読み直されます。

```json
{
  "input": ["Wireless microphone", "Brio 100"],
  "blockedInput": ["AirPods Max"],
  "output": ["外接耳機", "Mac Studio的揚聲器"],
  "blockedOutput": ["Maono AI Microphone"],
  "headphonesTakeOver": true,
  "balance": 0.5,
  "inputVolume": { "*": 100, "Wireless microphone": 88, "Brio 100": 75 },
  "liveness": { "Wireless microphone": { "zeroSeconds": 3 } },
  "reclaim": ["AirPods Max"],
  "outputVolumeHoldAgainst": ["Parallels Desktop"],
  "launchAtLogin": true,
  "errorReports": false
}
```

| フィールド | 型 | デフォルト | 意味 |
|---|---|---|---|
| `input` | 文字列の配列 | `[]` | 入力の優先順位。最も優先するものを先頭に。空ならルールはオフ |
| `blockedInput` | 文字列の配列 | `[]` | デフォルト入力にさせないデバイス |
| `output` | 文字列の配列 | `[]` | 出力の優先順位。空ならルールはオフ |
| `blockedOutput` | 文字列の配列 | `[]` | デフォルト出力にさせないデバイス |
| `headphonesTakeOver` | 真偽値 | `false` | Bluetooth 出力デバイスが接続されたら出力を引き継ぐ |
| `balance` | 数値または null | `null` | 0.0（左）から 1.0（右）。0.5 が中央。`null` でルールはオフ |
| `inputVolume` | オブジェクト | `{}` | デバイス名（すべての入力デバイスなら `"*"`）からパーセント（0〜100）への対応 |
| `liveness` | オブジェクト | `{}` | デバイス名から `{ "zeroSeconds": N }` への対応。N は 1 以上 |
| `reclaim` | 文字列の配列 | `[]` | ほかのデバイスに取られたら取り戻す Bluetooth ヘッドセット。名前またはアドレス |
| `reclaimEnabled` | 真偽値 | `true` | `reclaim` を空にせずに取り戻しをオフにする |
| `outputVolumeHoldAgainst` | 文字列の配列 | `[]` | 出力音量の変更を元に戻す対象のプログラム |
| `outputVolumeHoldEnabled` | 真偽値 | `true` | 一覧を空にせずに音量の引き戻しをオフにする |
| `launchAtLogin` | 真偽値 | `true` | ログイン時に Cleat を起動し、終了したら再起動する launchd エージェントを登録 |
| `errorReports` | 真偽値 | `false` | クラッシュとエラーのレポートを Sentry に送る。[プライバシー](#プライバシー)を参照 |

**入力音量。** `"*"` は現在あるすべての入力デバイスの目標値を設定し、名指しのエントリはそのデバイスについて上書きします。`{"*": 100, "Brio 100": 75}` は Brio を 75 に、それ以外をすべて 100% に保ちます。`"*"` がなければ、設定ファイルで名指ししていないデバイスには手を出しません。ワイルドカードはブロックされたデバイスにも及ぶので、`blockedInput` で入力の席から外した AirPods Max でも音量は保たれます。音量を読めないデバイス（一部の仮想デバイス）は、どちらの場合も触りません。

**ヘッドフォン。** Bluetooth 出力デバイスが現れると、それが出力になります。接続したまま手動で別のデバイスを選んだ場合は、その選択を尊重します。`headphonesTakeOver` がオンのとき、`output` は接続中の Bluetooth デバイスから音を移すことも、そこへ音を移すこともしません。ただし、そのデバイスが `blockedOutput` にある場合は別です。そのリストは「これは絶対に使わない」という意味で、「これはヘッドセットだ」より優先されます。つまり、ヘッドフォンが出力を持っていないときに何から鳴らすかを優先順位が決めます。macOS は有線ヘッドフォンについてはすでにこうしていますし、iOS も AirPods についてそうしています。しかし Mac の Bluetooth では、最後にスマートフォンとペアリングしていたヘッドセットを再接続しても音はスピーカーから出たままです。Cleat が埋めるのはその隙間です。Cleat の起動時にすでに接続されていたヘッドフォンは、いま到着したものとは扱わないので、Cleat を再起動しても出力が動くことはありません。

`blockedOutput` はもう半分の役割を担います。USB マイクの中にはスピーカー側の端子を持つものがあり、ヘッドフォンが外れると macOS はそこに落ちます。それは優先順位にないので、ブロックリストがなければ Cleat はあなたが選んだ出力だと解釈してそのままにします。ブロックされたデバイスは、優先順位に送り先がない場合でも外されます。リストにあるデバイスがすべて Cleat の触れられないヘッドセットのときは、ブロックされておらずヘッドセットでもない最初の出力に音を送り、そのようなデバイスがない場合にだけそのままにします。

**取り戻し。** Mac とスマートフォンの両方とペアリングした AirPods は、最後に要求した側のものになります。スマートフォンは何かを再生することで要求します。再生が止まっても Mac 側から改めて要求するものがないので、ヘッドセットはスマートフォンに残り（Bluetooth ではつながったまま、オーディオデバイスの一覧からは消えた状態）、Mac の音はその日ずっとスピーカーから出ます。macOS がヘッドセットを取り戻すのは、こちら側のアプリが再生を「始めた」ときだけで、その時点で音はすでに別の場所に出ています。

`reclaim` にヘッドセットを入れると、Cleat がそれを取り戻すよう依頼します。Cleat は macOS 自身が送るのと同じルーティング要求を送り、アクセサリが 2 台のデバイスそれぞれの状態から判断します。要求は「この Mac には再生セッションがある」と伝え、これは待機中のスマートフォンには勝ち、メディアを再生中や通話中のスマートフォンには負けます。つまり待機中のスマートフォンはヘッドセットを手放し、実際に使っているスマートフォンは手放しません。要求を送る前に 5 つの条件がすべて満たされている必要があります。ヘッドセットがリストにあること、この Mac に接続されていること、この Mac にオーディオデバイスとして現れていないこと、出力を持っているデバイスで何かが再生されていること、そして誰かが Mac の前にいること（直近 30 秒以内にキーボードかマウスに触れた、または最前面のアプリが動画を再生している）です。会議や `caffeinate` でスリープしないようにされている画面は、人がいるとはみなしません。手動で出力をヘッドセットから移した場合は、その再生の間はその選択を尊重します。スマートフォンが手放さなかったヘッドセットは、1 分待ってから改めて要求し、ログにも 1 回だけ書きます。要求が受け入れられると、ヘッドセットが出力になるまでにかかった時間、または戻ってこなかったことをログに書きます。

ヘッドセットは名前だけでなく Bluetooth アドレス（`"70:F9:4A:B6:0C:C9"`。ハイフンや小文字も可）でも指定でき、同じ名前の 2 台はこれで区別します。`cleat reclaim` は手動で要求を 1 回送って応答を表示するので、調停の結果を確かめるのに使えます。このルールは非公開のシステムインターフェイスを使っています。それがない macOS では、ルールは自分でオフになり、ログに一度そう書き、`cleat status` はオンではなく利用不可と表示します。

**出力音量。** CoreAudio は音量が変わったことは教えてくれますが、誰が変えたかは教えてくれないので、Cleat はシステムのオーディオログから変更したプログラムを読み取ります。`outputVolumeHoldAgainst` にあるプログラムによる変更は変更前の値に戻し、あなた自身や一覧にないプログラムによる変更は新しく保つ値になります。エントリは実行ファイル名かアプリ名で、`Parallels Desktop` は `Parallels Desktop.app` の中のあらゆるプログラムに一致します。

**デバイスの指定。** システム設定に表示される名前を使います。2 つのデバイスが同じ名前なら CoreAudio の UID を使います。名前は Unicode 正規化してから比較します。デバイスによっては、入力できない改行なしスペースを名前に含むものがあるからです（Maono のものなど）。大文字と小文字は正規化しません。

形式が壊れていたり値が範囲外だったりする設定ファイルが、動いている設定を置き換えることはありません。以前の設定が有効なまま残り、`cleat status` が理由を示します。設定が一度も読み込まれていない間は、すべてのルールがオフです。設定ファイルを削除してもすべてのルールがオフになります。これが Cleat を終了せずに止める方法です。

**無音検出**（`liveness`）は、マイクを開く唯一の機能です。Cleat は指定したデバイスで HAL IOProc を動かし、バッファ内のすべてのサンプルがちょうどゼロかどうかを調べます。本物のマイクには必ずノイズフロアがあり、送信機が切れた受信機は何も送りません。その状態が `zeroSeconds` 秒続くと、そのデバイスは存在しないものとして扱われ、優先順位の次のデバイスが引き継ぎます。入力を開いているので、Cleat が監視している間 macOS はオレンジ色のマイクのドットを表示します。

## コマンド

アプリ自体が CLI です。Homebrew の cask は、それを `cleat` としてリンクします。

```sh
cleat status      # what it is holding right now, and why
cleat log -n 50   # recent events
cleat restart     # start the daemon, or replace the running one, through its launchd agent
cleat reclaim     # ask for the headsets under "reclaim", once, and print the answer
cleat settings    # open the settings window
cleat version
```

Cleat が動いていないときは `cleat restart` を使ってください。エージェントがまだ登録されていなければ登録し、launchd にプロセスを置き換えさせます。ほかに手動で起動するものはありません。

`cleat status` は `~/Library/Application Support/Cleat-rs/status.json` を、`cleat log` は `~/Library/Logs/Cleat-rs/cleat-rs.log` を読みます。これらのコマンドはデーモンが書き出したファイルを読むだけで、デーモンと直接やりとりはしません。ログに残るのは実際に何かを変えた操作だけなので、静かなログは静かな一日を意味し、デーモンが壊れているわけではありません。生きているかどうかは `status` で確かめます。

## マイクの許可

必要なのは `liveness` だけです。Cleat を初めて実行したときに macOS が確認します。拒否しても、ほかのルールはすべて動き続け、`cleat status` に `microphone: denied` と表示されます。考えを変えたら、システム設定 > プライバシーとセキュリティ > マイク で許可してから `cleat restart` を実行してください。Cleat は起動時に許可を読むだけで、そのスイッチを監視しません。

Cleat が LaunchAgent に載せた単体のバイナリではなく .app になっている理由もここにあります。launchd が起動したコマンドラインツールは確認されないことが多く、要求が黙って失敗します。デーモンを監督するエージェントはアプリバンドル自身のバイナリ（`BundleProgram`）を起動するので、launchd が戻すプロセスは、マイクを許可したのと同じアプリです。

## プライバシー

頼まない限り、Cleat は Mac の外に何も送りません。唯一の例外はオプトインです。設定ファイルで `"errorReports": true` にすると、デーモンはクラッシュとエラーのレポートを Sentry に送ります。誰かが報告しなくてもクラッシュが作者に届くようにするためです。レポートに含まれるのは、スタックトレースまたはエラーメッセージ、Cleat と macOS のバージョン、時刻です。IP アドレス、ユーザー情報、設定ファイル、ファイルの内容は含まれず、ファイルパス中のホームフォルダは `~` に置き換えられます。Sentry はほかのサーバーと同じく、レポートが届いた接続を見ることができます。利用状況の追跡、セッションの追跡、画面録画はありません。

`false` に戻すか、その行を削除すれば、設定ファイルが読み直された時点で送信は止まります。再起動は不要です。`cleat status` で現在の設定がわかります。`cleat` コマンドと設定ウインドウは何も送りません。

## ソースからビルド

```sh
cd rs
cargo build --release
cargo test
bash scripts/bundle.sh    # target/bundle.noindex/Cleat.app
```

`scripts/bundle.sh` は、開発用 ID `ai.jetto.cleat.rs` で ad-hoc 署名したアプリを作ります。この ID はログインエージェントを登録しません。launchd のもとでテストする方法は `rs/README.md` にあります。

## アンインストール

```sh
brew uninstall --cask --zap cleat
```

手動でインストールした場合は、`launchctl bootout gui/$UID/ai.jetto.cleat` でエージェントを停止し、`/Applications/Cleat.app` を削除し、`~/Library/Application Support/Cleat-rs`、`~/Library/Logs/Cleat-rs`、`~/.config/cleat` を消してください。
